# Контракт для внешних продуктов (vvoice.item.v1)

Если вы делаете задачник, CRM или другую систему и хотите принимать задачи из этого приложения —
вам нужен ровно один адрес и одна форма данных.

## Что приходит

`POST` на ваш адрес (настраивается в `VV_EXPORT_WEBHOOK_URL`) с телом по схеме
[`schemas/vvoice.item.v1.json`](schemas/vvoice.item.v1.json):

```json
{
  "schema": "vvoice.item.v1",
  "item_id": "a3f1c2",
  "session_id": "9b7e44d1a2c05f13",
  "kind": "task",
  "title": "Отправить смету до пятницы",
  "owner": "Дмитрий",
  "due_at": "2026-11-27T10:00:00+05:00",
  "priority": "high",
  "evidence": {
    "quote": "Я отправлю смету завтра утром, успеем.",
    "start_s": 412.5,
    "end_s": 419
  },
  "approved_by": "Аляев Дмитрий"
}
```

## Пять видов элементов

`kind` принимает пять значений, и это не оттенки одного: у каждого свой смысл и своя реакция.

| `kind` | Что это | Что делать у себя |
|---|---|---|
| `task` | Поручение | Обычная задача. `owner` и `due_at` могут быть пустыми |
| `meeting` | Договорились созвониться или встретиться | Событие в календаре. Без `due_at` время не называли — не выдумывайте его |
| `reminder` | «Напомни про…» | Напоминание со сроком. Без `due_at` оно не сработает никогда — заведите без времени и попросите человека уточнить |
| `decision` | Что решили | Запись «о чём договорились», а не действие. Сроков не имеет |
| `question` | Что осталось открытым | Вопрос без ответа. Полезно в карточке встречи, вредно — в списке задач |

Если ваш продукт умеет только задачи, остальные четыре всё равно принимайте: отброшенная встреча
вернётся к человеку как потерянная.

## Три правила, которые нельзя нарушать у себя

1. **Принимайте только то, что пришло с `evidence.quote`.** Задача без цитаты — это чей-то домысел,
   и если вы её сохраните, через месяц никто не вспомнит, откуда она.
2. **`owner` и `due_at` могут быть `null`.** Это не ошибка: в разговоре их просто не называли.
   Не подставляйте «логичного» исполнителя сами.
3. **`item_id` + `session_id` уникальны.** По этой паре отбрасывайте повторы: повторная отправка
   после обрыва сети — обычное дело.

## Что приходит в ответ

Любой код `2xx` означает «принято». Всё остальное приложение покажет человеку как отказ по этой цели
и **не** будет делать вид, что задача дошла.

## Как забрать разбор, не отправляя задачи

Иногда задачник не нужен — нужно просто показать встречу в своём продукте (CRM-карточка,
домашняя страница проекта, отчёт за неделю). Для этого разбор можно прочитать.

**`GET /api/v1/sessions/{session_id}/digest`** — заголовок `Authorization: Bearer <токен>`.

Что в ответе. **Разбор лежит наверху** (так с версии контракта 1.16; поля `digest.*` ниже читаются как есть,
без `digest.`). Реплики и служебные числа — рядом с ним, в том же объекте:

| Поле | Что это | Чего ждать |
|---|---|---|
| `summary` | Краткая выжимка, списком | пустой список — нормально, это не ошибка |
| `summary_missing` | `true`, если модель ничего не выделила | покажите свой текст, а не пустое место |
| `truncated` | `true`, если разговор длиннее одного прохода | честно скажите «разобрано начало» |
| `participants` | Кто говорил и чей это голос (`owner` / `member` / `foreign`) | `foreign` в задачи не идут по вашей же просьбе |
| `items` | Только элементы с цитатой | элемент без цитаты отброшен валидатором |
| `rejected` | Что отброшено и почему | полезно показать, если человек удивлён |
| `utterances` | Реплики с таймкодами (`speaker`, `start_s`, `end_s`, `text`) | из них строятся субтитры и поиск по времени |
| `errors` | Список ошибок, если разбор сохранился частично | покажите, прежде чем строить отчёт |
| `speakers` | Метки всех голосов записи | по ним можно построить фильтр «только я говорил» |
| `sent_chunks` | Сколько кусков аудио ушло в распознавание | мера нагрузки на провайдера |
| `sent_seconds` | Сколько секунд аудио ушло в распознавание | основа расчёта стоимости встречи |
| `cost_rub` | Стоимость встречи, если тариф задан | без тарифа поля нет: ноль не значит «бесплатно» |
| `budget_exceeded` / `budget_rub` | Предел на встречу превышен | показать сразу, а не в счёте за месяц |

Отдельно — расшифровка: `GET /api/v1/sessions/{session_id}/transcript?format=txt|md|srt|vtt|json`.
Для субтитров берите `srt`, для поиска по тексту — `json`.

Записи на этом маршруте **не отправляются** наружу: чтение безопасно и не создаёт задач.
Отправка — только `POST /api/v1/sessions/{session_id}/export`, отдельным действием.

## Как проверить свою интеграцию

Направьте `VV_EXPORT_WEBHOOK_URL` на свой адрес, продиктуйте телефону любой разговор с явной
договорённостью, подтвердите пункт и отправьте. Ожидаемое: ровно один запрос на каждый пункт,
в теле — цитата и таймкод.

## Ключи приёмников

У каждой цели свой ключ — Helper, Jira и Bitrix24 ждут **разные** токены:

```bash
VV_EXPORT_HELPER_URL=https://helper.vernadsky-npc.ru
VV_EXPORT_HELPER_TOKEN=<Bearer Прохора>
VV_EXPORT_JIRA_URL=https://your.atlassian.net
VV_EXPORT_JIRA_TOKEN=<токен Jira>
VV_EXPORT_TOKEN=<запасной для всех, если своего нет>
```

Свой ключ цели важнее общего. Без ключа вообще задача уходит без заголовка: свой приёмник
внутри сети может быть открыт, а чужой честно откажет и скажет об этом.

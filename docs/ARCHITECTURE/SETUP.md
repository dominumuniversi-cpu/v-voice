# Настройка сервера: по шагам

Одна страница для человека, который ни разу не запускал этот сервис. Модели подключаются
**на сервере**, телефон ничего не настраивает.

## Что понадобится

| Что | Зачем | Где взять |
|---|---|---|
| Python 3.12 | сервис написан на стандартной библиотеке | python.org |
| Ключ распознавания речи | превращать голос в текст | **Speechmatics** — единственный, что уже подключён в коде (Deepgram/AssemblyAI пока задачи, а не настройки) |
| Ключ модели | превращать текст в задачи и выжимку | DeepSeek, Anthropic или Ollama — эти три уже подключены |
| Адрес задачника | куда отправлять одобренные задачи | тот же Helper, что уже работает |

## Шаг 1. Каталог и файл настроек

```
cd services/api
copy .env.example .env          # Windows
# cp .env.example .env          # Linux/macOS
```

## Шаг 2. Заполнить .env

```
VV_ASR_PROVIDER=speechmatics
VV_ASR_KEY=<ключ распознавания>
VV_ASR_PRICE_PER_HOUR=
VV_BUDGET_PER_MEETING=
VV_LLM_PROVIDER=deepseek
VV_LLM_KEY=<ключ модели>
VV_EXPORT_HELPER_URL=https://helper.vernadsky-npc.ru
```

### Замок на сервер (нужен везде, кроме своего компьютера)

Если сервер стоит в интернете или в общей сети, допишите строку — иначе разговор сможет открыть
кто угодно, кто знает адрес:

```
VV_DEVICE_TOKENS=<длинная случайная строка>
```

Тот же токен вводится один раз в приложении на телефоне. Поле пустое — замка нет: на своём
компьютере это нормально, в интернете — нет.

Пустая строка означает «не подключено» — это не ошибка, сервис запустится и честно скажет,
что именно недоступно.

### Остальные настройки — по желанию

| Переменная | Зачем | Нужна ли |
|---|---|---|
| `VV_NOISE_GATE` | порог отсечения гула на сервере | по умолчанию разумный, трогать не нужно |
| `VV_EXPORT_JIRA_URL` | отправлять задачи в Jira | только если задачи идут в Jira |
| `VV_EXPORT_BITRIX_URL` | отправлять задачи в Bitrix24 | только если задачи идут в Bitrix24 |
| `VV_EXPORT_WEBHOOK_URL` | свой адрес-приёмник задач | для своей CRM или скрипта |
| `VV_EXPORT_TOKEN` | общий токен приёмника: уходит заголовком `Authorization` | если задачник или CRM требует ключ (задачник NPC — `npc-agent-…`) |
| `VV_EXPORT_HELPER_TOKEN`, `VV_EXPORT_JIRA_TOKEN`, `VV_EXPORT_BITRIX_TOKEN` | свой ключ на каждую цель: Helper, Jira и Bitrix24 ждут разные токены | когда принимающих сервисов больше одного; важнее общего токена |
| `VV_HOST` | на каком адресе слушать | по умолчанию `127.0.0.1` — виден только этому компьютеру; `0.0.0.0` открывает его в сеть, и тогда обязателен `VV_DEVICE_TOKENS` |
| `VV_ENV_FILE` | путь к другому файлу настроек | когда .env лежит не рядом с программой |
## Шаг 3. Запуск

```
set VV_DATA_DIR=C:\vvoice\data
set VV_PORT=8080
python main.py
```

В консоли появятся две строки — готовность распознавания и понимания. Если написано
«НЕ настроено», значит в .env чего-то не хватает, и дальше искать надо там, а не в телефоне.

## Шаг 4. Проверка, что ключи подхватились

```
curl http://127.0.0.1:8080/api/v1/health
```

В ответе `settings` покажет провайдеров, готовность и **отпечаток** ключа (8 символов).
Самого ключа в ответе нет и не будет: по отпечатку видно, что подхвачен тот ключ,
который вы вставили, но восстановить его из отпечатка нельзя.

## Шаг 5. Телефон

В приложении открыть «Подключение моделей»: адрес сервера и строка состояния моделей.
Ключи там не вводятся — они живут на сервере.

## Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| `/health` отвечает, но can_transcribe: false | нет ключа или неизвестный провайдер | сверить имена переменных в .env с таблицей выше |
| сервис не стартует | занят порт | поменять VV_PORT |
| «Разбор недоступен» на телефоне | сервер без ключей модели | шаг 2 |
| ключ не подхватился после правки `.env` | переменные читаются при старте | перезапустить службу |
| ключ не подхватился после экрана «Подключить модели» | перезапускать не нужно | ключ живёт до перезапуска: проверить «Проверить сохранённую связку» и отпечаток ключа |

### Сервер в сеть — только с замком

Сервер хранит чужие разговоры, поэтому с внешним адресом (`VV_HOST=0.0.0.0`) он **не запустится без `VV_DEVICE_TOKENS`**: замка нет — значит любой в той же Wi-Fi прочитал бы расшифровки. Задайте список ключей устройств или оставьте `127.0.0.1`.

## Порядок настройки со стороны человека

1. Токен устройства — его выдаёт сервер (`VV_DEVICE_TOKENS`); вставить в поле «Токен» и запомнить адрес стенда.
2. Экран «Подключить модели»: выбрать связку для разбора (или Ollama на своём сервере) и связку для распознавания.
   Ключ нужен только платным; у Ollama вместо ключа — адрес сервера.
3. Кнопка «Проверить сохранённую связку» — она делает настоящий запрос и говорит причину, если что-то не так.
4. Только после этого идти записывать: до проверки «зелёная галочка» ничего не значит.

## Выбор модели и адреса

`VV_LLM_MODEL` — какую модель зовём. Пусто — модель провайдера по умолчанию.
`VV_LLM_BASE_URL` — адрес сервера модели. Нужен для своего Ollama: `127.0.0.1` внутри контейнера —
это сам контейнер, а не хост, поэтому адрес указывается явно (например `http://192.168.8.49:11434`).
`VV_ASR_MODEL` — модель распознавания, если у провайдера их несколько.

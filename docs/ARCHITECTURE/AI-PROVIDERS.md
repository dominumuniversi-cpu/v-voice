Здесь три слоя: **распознавание речи (ASR)**, **диаризация** (кто говорит), **LLM-разбор** (что поняли).
Для каждого — рекомендуемые варианты, требование к железу, переменные окружения и **как подключить руками**.
Все ключи хранятся **только на сервере** (env или `secrets/` — вне git); в мобильное приложение не попадают.

## Что уже подключено в коде

Это не план, а факт на сегодня. Сверяйте с ним, прежде чем покупать ключ: остальные варианты ниже
описаны как кандидаты, а не как готовые.

| Слой | Реализовано | Что будет, если выбрать другое |
|---|---|---|
| Речь (ASR) | `fake` (демо, без ключа), `speechmatics`, `whisper` (своя модель, без ключа) | Сервер при старте скажет «провайдер настроен, но реализации нет» |
| Понимание (LLM) | `fake`, `deepseek`, `anthropic`, `ollama` | То же самое, только про понимание |

Остальные провайдеры (Deepgram, AssemblyAI, GigaAM) есть в списке допустимых имён и описаны ниже,
но кода у них пока нет — это задачи, а не настройки.

## Зависимости сервера

Сервер работает на стандартной библиотеке Python, кроме одной вещи: живому распознаванию нужен
WebSocket. Библиотека ставится из `services/api/requirements.txt`:

```bash
pip install -r services/api/requirements.txt   # websocket-client
```

Если её нет, `/health` покажет `ws_client: false`, а разбор записи через файл останется доступным.
Это не ошибка старта: сервер поднимется и скажет правду, а не будет молча простаивать.

## Как убедиться, что модели подключены

Откройте `/api/v1/health` (с ключом устройства из `VV_DEVICE_TOKENS`). Смотрите три поля:

| Поле | Что значит |
|---|---|
| `asr.ready` | можно распознавать речь: провайдер есть в коде, ключ заполнен |
| `asr.ws_client` | есть чем открыть соединение с сервисом распознавания |
| `llm.ready` | модель понимания подключена и получит разговор |

Пока хотя бы одно `false`, «разбор» не начнётся — и это видно до того, как кто-то начнёт встречу.
## 0. Пошагово: как подключить за 10 минут

Что нужно сделать руками, по шагам. Всё настраивается на экране «Подключить модели» (значения из .env сервер видит, но экран их перекрывает).

### Шаг 1. Выберите набор

| Если вы… | Берите пресет |
|---|---|
| **«Точно»** | Речь: Speechmatics (облако), разбор: DeepSeek. Лучшее качество, данные в облаке. |
| **«Быстро и дёшево»** | Речь: Deepgram (облако), разбор: DeepSeek. Экономно, русский чуть хуже. |
| **«Только локально»** | Речь: GigaAM на вашем сервере, разбор: Ollama. Ничего не уходит наружу — нужен GPU. |

### Шаг 2. Получите ключ

| Провайдер | Где брать | Что важно |
|---|---|---|
| Speechmatics | console.speechmatics.com → API keys | оплата по времени, ключ вида длинной строки |
| Deepgram | console.deepgram.com → API Keys | есть бесплатный лимит на старт |
| DeepSeek (разбор) | platform.deepseek.com → API keys | дешёвый, отдельный ключ от ASR |
| GigaChat (разбор) | developers.sber.ru | нужен authorization key и client_id |

### Шаг 3. Вставьте ключ на экране «Подключить модели»

1. На главном экране — значок **настроек** (справа сверху).
2. Сверху укажите **адрес сервера** и нажмите «Сохранить». Если адрес с опечаткой — приложение скажет, в чём именно.
3. Выберите пресет, нажмите на карточку нужной модели и вставьте ключ.
4. Нажмите **«Проверить»**. Ответ бывает трёх видов:

| Ответ | Что это значит |
|---|---|
| Ключ рабочий | можно записывать |
| Ключ не принят | проверьте, что скопировали ключ целиком, без пробелов |
| Нет связи с сервером | проверьте адрес сервера из шага 2 |

### Важно: куда девается ключ после проверки

**На телефоне ключ не хранится.** Поле «Ключ доступа» нужно для одной вещи: проверить, что ключ рабочий.
Кнопка «Проверить» отправляет его на сервер, сервер задаёт один вопрос поставщику и **ключ не запоминает**.

Дальше ключ живёт только на сервере. Это правило проекта, и оно не выдумано: ключ в телефоне —
это ключ, который уносят вместе с телефоном, а его владелец узнает об этом последним.

Как положить ключ на сервер (одна строка на каждый провайдер, файл `.env` рядом с сервером, вне git):

```
VV_ASR_PROVIDER=speechmatics
VV_ASR_KEY=<ключ, который вы проверяли>
VV_LLM_PROVIDER=deepseek
VV_LLM_KEY=<ключ для разбора>
```

После этого поле на телефоне можно оставить пустым: приложению ключ больше не нужен.

### Шаг 4. Проверьте на короткой записи

Скажите вслух одну фразу с явной задачей («завтра отправлю смету Ивану»), остановите запись и посмотрите разбор.
Если задача появилась с цитатой — всё работает. Если появилась без цитаты — это ошибка, присылайте: правило такое запрещает.

## 2. ASR — варианты подключения

### 2.1 GigaAM-v3 (self-host, рекомендовано как основной для русского)
- Модель: `ai-sage/GigaAM-v3`, ревизия `e2e_rnnt` (текст сразу с пунктуацией), MIT, ~220–240M параметров.
- Железо: **GPU** (одна карта уровня RTX 4090 / L4 / A10 хватает на несколько потоков), VRAM ≈ 4–8 ГБ
  с запасом; CPU-инференс возможен, но не для онлайна.
- Сервер: Python 3.11+, `torch==2.8.0`, `torchaudio==2.8.0`, `transformers==4.57.1`, `trust_remote_code=True`.
- Подключение:
  ```bash
  # .env сервера
  ASR_PROVIDER=gigaam
  GIGAAM_MODEL=ai-sage/GigaAM-v3
  GIGAAM_REVISION=e2e_rnnt
  GIGAAM_DEVICE=cuda        # или cpu
  GIGAAM_CHUNK_SEC=4
  ```
- Проверка: `POST /api/v1/providers/gigaam/test` с эталонным файлом → ожидаем текст с пунктуацией.

### 2.2 Speechmatics (облако, лучший заявленный онлайн + диаризация в стриме)
- Значения: realtime Melia 1 $0,20/ч, Enhanced $0,40/ч; pre-recorded Melia $0,12/ч (цены проверены 26.11.2026).
- Подключение:
  ```bash
  ASR_PROVIDER=speechmatics
  SPEECHMATICS_API_KEY=xxxxxxxx      # в secrets/, не в git
  SPEECHMATICS_LANG=ru
  SPEECHMATICS_DIARIZATION=true
  ```
- Проверка: «Проверить» в настройках → тестовый запрос на 5 c.

### 2.3 Deepgram (облако, быстрый коннект, оплата по секундам)
```bash
ASR_PROVIDER=deepgram
DEEPGRAM_API_KEY=xxxxxxxx
DEEPGRAM_MODEL=nova-3
DEEPGRAM_DIARIZE=true
```
Цена потокового: $0,29/ч (монолингв.), $0,35/ч (мультиязычный), тишина бесплатно.

### 2.4 AssemblyAI (облако, точность на записях)
```bash
ASR_PROVIDER=assemblyai
ASSEMBLYAI_API_KEY=xxxxxxxx
```
Pre-recorded $0,21/ч; в MVP используем как **финальный проход по всему аудио** (точнее, чем стрим).

### 2.5 SaluteSpeech / GigaChat Audio / Yandex SpeechKit (РФ, для 152-ФЗ)
Подключение — только после проверки цен и юр. условий (задача «Исследовать и уточнить требования»).
План интерфейса:
```bash
ASR_PROVIDER=salutespeech
SALUTESPEECH_AUTH_KEY=...
SALUTESPEECH_SCOPE=SALUTE_SPEECH_PERS
```

### 2.6 Локальный ES-совместим: iOS 26 `SpeechAnalyzer` (опция приватности, фаза 2)
Нативный модуль приложения, не сервер. Плюс — on-device без сервера; минус — только iOS 26+, не решает
фоновую запись. Использовать как «приватный режим для iPhone».

## 4. LLM-разбор

Строгая JSON-схема + evidence-правило (см. ниже). Модель должна уверенно держать структурированный вывод.

| Провайдер | env | Замечания |
|---|---|---|
| **DeepSeek** | `LLM_PROVIDER=deepseek`, `DEEPSEEK_API_KEY` | дешево, хорошо держит JSON, русский OK |
| **GigaChat** | `LLM_PROVIDER=gigachat`, `GIGACHAT_CREDENTIALS` | РФ, 152-ФЗ |
| **Claude** | `LLM_PROVIDER=anthropic`, `ANTHROPIC_API_KEY` | лучший разбор длинных встреч, дороже |
| **Локальная** | `LLM_PROVIDER=ollama`, `OLLAMA_BASE_URL=http://gpu:11434` | приватный контур |

### Схема ответа (контракт)
```json
{
  "summary": ["..."],
  "participants": [{"speaker":"S1","name":"Анна","verdict":"owner"}],
  "items": [
    {"kind":"task|meeting|reminder|decision|question",
     "title":"...", "owner":"...", "due_at":"ISO8601|null", "priority":"low|medium|high",
     "evidence":{"start_s":0,"end_s":0,"quote":"..."}}
  ],
  "open_questions": ["..."]
}
```
**Правило:** элемент без `evidence.quote` (≥ 12 символов, есть в транскрипте) **отбрасывается валидатором**.

## Проверка подключения (кнопка «Проверить»)

Человек вводит ключ и получает ответ словами, а не кодом:

| Ситуация | Что увидит человек |
|---|---|
| ключ пустой / с пробелом / обрезан | «В ключе есть пробел…», «Ключ слишком короткий: похоже, скопирована только часть» |
| 200 | «Ключ рабочий, сервис отвечает» |
| 401 | «Ключ неверный или отозван» |
| 402 | «Нет оплаченного баланса» — самая частая причина сбоя перед встречей |
| 403 | «Ключ без нужного уровня или выключен в кабинете» |
| 429 | «Лимит запросов, ключ рабочий, подождите» |
| нет сети | «Нет ответа от сервиса: проверьте интернет или адрес» |
| неизвестный код | честно: «не знаю, сообщите администратору», а не ложное «работает» |

При плохом ключе сетевой запрос вообще не отправляется. Код: `services/api/vvoice/provider_probe.py`,
пресеты «точно / дёшево / приватно» — там же (`presets()`).

## Модели разбора по провайдерам (описано, в коде не подключено)

| Провайдер | Модель по умолчанию | Особенность подключения |
|---|---|---|
| **DeepSeek** | `deepseek-chat` | OpenAI-совместимый чат, режим строгого JSON (`response_format`), ключ в `VV_LLM_KEY` |
| **Claude (Anthropic)** | `claude-sonnet-4-5` | системный промпт отдельным полем `system`, заголовок `anthropic-version: 2023-06-01` |
| **GigaChat** | `GigaChat-2-Max` | российский контур: данные не выходят из РФ, ключ в кабинете Сбера |
| **Ollama (локально)** | `qwen3:8b` | ключ не нужен, всё на своей машине: `http://127.0.0.1:11434` |

Один и тот же вызов для всех: `make_caller(provider, model, key, send) -> call(system, user) -> dict`.
Сборка запроса и разбор ответа — чистые функции (`build_request`, `extract_text`, `parse_json_answer`),
поэтому отличающийся протокол у каждого сервиса не протекает в конвейер.
Тесты: сборка запросов для всех четырёх, разбор ответов в трёх разных форматах, JSON в прозе модели.

## Как это настраивает человек (экран «Подключить модели»)

Вопрос владельца был прямой: «ключ — ещё не подключение, с чем этот ключ будет работать?».
Поэтому на экране настроек нет пустых полей «url» и «token». Есть готовые связки, и человек
выбирает название, а не вводит адрес по памяти.

| Связка | Что даёт | Что нужно от человека | Стоимость |
|---|---|---|---|
| DeepSeek | разбор текста в задачи | ключ с platform.deepseek.com | платно, копейки за встречу |
| Claude Sonnet | тот же разбор, аккуратнее с форматом | ключ с console.anthropic.com | платно |
| Ollama на своём сервере | разбор без интернета | запущенный ollama + скачанная модель + **адрес** | бесплатно, своё железо |
| Speechmatics | распознавание русской речи | ключ с portal.speechmatics.com | платно, есть пробный период |
| Демо-заглушка | показать весь путь без сети | ничего | бесплатно, текст выдуман |

Тонкость, на которой спотыкаются почти все: **адрес Ollama обязателен**. `127.0.0.1` внутри
контейнера — это сам контейнер, а не сервер с моделью. Поэтому поле «Адрес сервера» появляется
ровно там, где оно нужно, и сохраняется вместе с моделью (`VV_LLM_MODEL`, `VV_LLM_BASE_URL`).

## Выбор модели из списка, а не по памяти

Имя модели, вписанное по памяти, — частая причина «модель не ответила». Поэтому рядом с полем
«Модель» есть подсказка: `GET /api/v1/models` отдаёт то, что доступно для выбранной связки.
Для DeepSeek и Claude это известный каталог. Для **Ollama** — живой запрос к серверу человека
(`/api/tags`): список берётся из его же машины. Если адрес не указан, ответ честно говорит об
этом, а не показывает пустоту. Список — подсказка, а не запрет: своё имя вписать можно всегда.

## Ключ — не подключение: кнопка «Проверить связь»

Сохранение настроек проверяет только форму (выбран ли провайдер, есть ли ключ). Это не значит,
что модель отвечает: ключ мог истечь, адрес — отвалиться, модель — переименоваться. Поэтому есть
отдельная кнопка, которая делает настоящий короткий запрос к модели (`POST /api/v1/models/check`)
и отвечает словами: «связь есть» или конкретная причина («модель ответила 401: ключ неверен»).
Проверено вживую: на подставном ключе API вернул `ok: false` с текстом про 401 — то есть кнопка
не врёт ради зелёной галочки.

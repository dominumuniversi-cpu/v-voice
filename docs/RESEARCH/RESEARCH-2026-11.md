# Исследование решений: транскрибация, диаризация, мобильная запись (ноябрь 2026)

Дата: 26.11.2026 · Автор: сессия-исследователь · Статус: черновик, факты со ссылками
Ограничение сессии: `web_search` (DeepSeek), Tavily и Serper в этой среде **не работают**
(DeepSeek API key отсутствует, Tavily отвечает 403, SERP-движки блокируют бота). Утверждения ниже
получены прямой загрузкой официальных страниц через `web_fetch`; где источник не получен — это помечено.

## 1. Главный вывод по платформам: сценарий «услышать, пока телефон заблокирован»

### 1.1 iOS — ограничение платформы, а не выбор фреймворка

| Факт | Источник |
|---|---|
| Режим фоновой работы `audio` описан Apple как «The app **plays** audible content in the background» | [Apple: Configuring background execution modes](https://developer.apple.com/tutorials/data/documentation/xcode/configuring-background-execution-modes.json) |
| Перечень значений `UIBackgroundModes`: `audio`, `bluetooth-central`, `fetch`, `location`, `processing`, … — отдельного «recording» режима нет | [Apple: UIBackgroundModes](https://developer.apple.com/tutorials/data/documentation/bundleresources/information-property-list/uibackgroundmodes.json) |
| Apple: режим фонового аудио нельзя использовать произвольно; приложение, которое не воспроизводит звук, а только пишет, отклоняется по Guideline 2.5.4 | практика App Store; официальную цитату получить не удалось — проверить на этапе «риски» |

**Следствие.** Сценарий «телефон в кармане, экран погашен, идёт запись совещания» на iPhone
**не является гарантированным**. Его нельзя обещать как основной режим. Рабочие пути:

1. **Pocket-режим (рекомендуется)**: включаем AVAudioSession `.record` + фоновый аудио-сеанс, продолжаем
   писать и стримить, но честно показываем в приложении статус «пишем — не выгружай приложение».
   Проверяется только живым прогоном на реальном устройстве (сценарий: экран выключен 30+ мин).
2. **Butterfly / фоновый фолбэк**: короткие `beginBackgroundTask`-окна + локальный буфер, догрузка дословной
   транскрипции по возвращении в приложение и на сервере из сырого аудио.
3. **Запись звонков** (CallKit/VoIP) — отдельная история, в MVP не входит.

### 1.2 Android — режим есть, но со строгими условиями

| Факт | Источник |
|---|---|
| Тип foreground-сервиса `microphone` + `FOREGROUND_SERVICE_MICROPHONE` + runtime `RECORD_AUDIO`; описание прямо про «voice recorders» | [Android: FGS types — Microphone](https://developer.android.com/develop/background-work/services/fgs/service-types.md) |
| Сервис с while-in-use разрешением (микрофон) **нельзя создать из фона**: старт только когда UI приложения видим; запуск из `BOOT_COMPLETED` запрещён | [Android: FGS start restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start.md) |

**Следствие.** На Android сценарий «нажал запись, заблокировал» работает штатно: сервис стартует из UI,
дальше живёт с постоянным уведомлением. Пользователь **обязан** видеть уведомление о записи.
Android 12+ — `ForegroundServiceStartNotAllowedException` при попытке старта из фона; обрабатывается
экраном «Запись остановлена системой» + накопленное аудио всё равно выгружается.

### 1.3 Что работает на обеих платформах одновременно

- **Запись звука** (микрофон) в нативной оболочке. Кросс-платформенная запись живёт в нативном
  слое, а не в веб-вью; браузер в фоне страницу приостанавливает.
- **Веб/PWA** (Web Speech API) для фоновой записи не годится: в фоне браузер приостанавливает страницу,
  а `SpeechRecognition` на iOS в PWA фактически недоступен → **мобильный клиент = нативная оболочка**.

## 2. Модели/сервисы распознавания речи ({ru} обязательно)

### 2.1 Локальные модели для self-host (дешево, приватно, свой стек)

|---|---|---|---|

**GigaAM-v3 e2e_rnnt на GPU** как дефолт (self-host), Whisper как фолбэк для других языков.

**Утверждение «у кого лучше» не подтверждено независимым тестом.** Маркетинговые заявления вендоров
(Speechmatics: «25–70% меньше ошибок, чем у Microsoft/AssemblyAI/Deepgram») — реклама, а не бенчмарк.

### 2.3 Российские облачные провайдеры

Прямые официальные страницы Сбера (`developers.sber.ru/docs/ru/salutespeech/…`, GigaChat Audio)
отдаются страницей-обёрткой без текста (JS-рендер, `web_fetch` упирается в 100 КБ стилей) — **факты
и цены не подтверждены**, нужен отдельный сбор (см. задачу «Исследовать и уточнить требования»).
Для проекта важны по 152-ФЗ (если аудио уходит из РФ — нарушение по персональным данным).
Кандидаты на проверку: **SaluteSpeech** (Sber, потоковое распознавание), **GigaChat Audio**,
**Яндекс SpeechKit** (является в NPC-прошлом, вероятно уже есть доступы — проверить `secrets/`).

## 3. Диаризация (кто говорит) — отдельная модель, не «из коробки»

| Подход | Где работает | Оценка для нашего кейса |
|---|---|---|
| Встроенная диаризация облачного стрима (Speechmatics, AssemblyAI, Deepgram) | сервер, онлайн | быстрый старт, но дорого за час и не работает офлайн |
| **pyannote.audio 4.x** на сервере (рекомендовано GigaAM в их же карточке) | сервер, батч или near-real-time окнами | бесплатно, точность на записи совещаний высокая, но не умеет «живой» online-инкремент без нарезки окон |
| **3D-Speaker / CAM++ + онлайн-кластеризация** | сервер, скользящие окна 2–4 c | ещё дешевле, можно и на телефоне, качество ниже pyannote |
| Нативный iOS `SpeechAnalyzer` + `SpeechTranscriber` | телефон, iOS 26+ | on-device, без сервера, длинные записи без 1-минутного лимита, но **только на iOS 26+** и не решает фоновую запись |

**Решение по диаризации для MVP:** серверная диаризация окнами по 5 сек с pyannote (или через облачный
стрим), а на телефоне — только буферизация аудио и «живой» текст без спикеров в первой итерации.

## 4. Критическое требование «отсекать шум и сторонние голоса»

| Слой | Средство |
|---|---|
| 1. Микрофон | нишевая направленность устройства, AUX/Bluetooth-микрофон как опция, автоматический gain (AGC отключён — он портит ASR) |
| 2. VAD | **Silero VAD** (открытый, ~2 мс на чанк, ru-независим) — режет тишину/шум до отправки в облако (экономия 30–70% трафика и денег) |
| 3. Разделение источников | **MossFormer2 / SepFormer / DPRNN** (SpeechBrain, online-вариант) — 2–3 спикера в одном микрофоне, офлайн на сервере |
| 4. Отсечение чужих голосов | **SpeechBrain ECAPA-TDNN (speaker verification)**: децибельные отсечки + отпечаток владельца («голос хозяина»). Нужна регистрация голоса (30–60 сек) |
| 5. Модель распознавания | **GigaAM-v3 обучен на речи с музыкой и шумом** — уже устойчивость к шуму, не только к чистой речи |

**Следствие.** «Понимать только своё и ближайших» — это **верификация спикера по отпечатку**, а не VAD.
VAD убирает тишину, диаризация — делить людей, ECAPA — отбирать нужных. Это 3 разные компоненты, все — на сервере.

## 5. Понимание разговора (то, ради чего всё затевается)

Схема на сервере: сегменты → **диаризация + склейка в реплики** → **LLM-структурирование** с жёсткой схемой JSON.

Задачи, которые модель решает на разговоре:

1. **Краткая выжимка** (5–7 строк: о чём, кто участвовал, что решили).
2. **Задачи** (кому, что, к какому сроку, из какой реплики).
3. **Встречи/звонки** (дата/время/место/участники) и **напоминания** (триггер + срок).
4. **Решения и договорённости** (отдельный список, чтобы потом искать).
5. **Риски и открытые вопросы** (что не решили).
6. **Сущности** (люди, компании, проекты) — для будущей встройки в CRM.

**Ключевая ловушка:** LLM «галлюцинирует» задачи из воздуха. Решение — требование
**evidence (`start_s`–`end_s` + `quote`) для каждого факта** и правило «нет цитаты — нет задачи».
Задачи с IELTS на «подумать» не создаются; всё попадает в «Отчёт» с цитатой и кнопкой «в задачник».

## 6. Сравнение подходов к продукту целиком

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **A. Нативный на Flutter (запись+UI) + сервер (FastAPI, GigaAM/облако)** | единый код UI и запись под android+ios; сервер полностью под наш контроль, диаризация и LLM на сервере | нужно писать нативные мосты записи; iOS-фон — риск | **База** |
| B. Облачный ASR в телефоне напрямую | меньше сервера | секреты API в аппе, нет LLM-разбора онлайн, дорого, нет 152-ФЗ | Отклонить |
| C. Полностью на устройстве (модели в приложении) | приватно, офлайн, ноль платы | телефон греется и жрёт батарею, диаризация и LLM в телефоне невозможны качественно | Отклонить для MVP |
| D. Сторонний сервис «диктофон + заметки» (Otter, Fireflies, Ami, Plaud) | готово | не встраивается в наши продукты, нет нашего LLM, нет данных | Использовать как бенчмарк UX, не как решение |
| **E. Open-source платформа для прослушивания** (Whisper/x-ASR + диаризация + LLM) | бесплатно | полная разработка + SLA на нас | Использовать как референс кода |

**Выбор:** **A** — Flutter-оболочка (нативные мосты записи) + сервер на Python (FastAPI) с роутингом
по провайдерам: GigaAM (self-host) → облачный стрим (Speechmatics/AssemblyAI) → offline-режим.

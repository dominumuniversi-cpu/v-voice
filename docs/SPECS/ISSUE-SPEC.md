# Задачник репозитория: как заводить задачи

Все задачи, баги и бэклоги проекта — **только в GitHub Issues** репозитория [dominumuniversi-cpu/v-voice](https://github.com/dominumuniversi-cpu/v-voice).
Это правило проекта (AGENTS.md) и требование владельца. Других задачников нет: то, чего нет в issues, не делается.

## Метки

| Группа | Значения | Смысл |
|---|---|---|
| Область | `area/mobile`, `area/audio`, `area/asr`, `area/llm`, `area/backend`, `area/design`, `area/infra`, `area/security`, `area/legal`, `area/docs`, `area/research` | что затрагивает |
| Тип | `type/feature`, `type/bug`, `type/research`, `type/spike`, `type/task` | что производят |
| Этап | `phase/S0` … `phase/S8` | к какому спринту относится |
| Приоритет | `p0` (блокер), `p1` (сейчас), `p2` (должно), `p3` (потом) | когда делать |
| Вопрос | `needs-answer` | ждёт ответа владельца |

## Вехи (Milestones)

M0 «Основа» → M1 «Слышим» → M2 «Понимаем» → M3 «Чистим звук» → M4 «Встраиваем» → M5 «Настраиваем» → M6 «Надёжность».
Веха ставится каждой задаче: без вехи задача не попадает в дорожную карту.

## Обязательная структура задачи

1. **Заголовок** — результат, не действие: «Фоновая запись на Android держит сутки», а не «сделать сервис».
2. **Проблема** — почему задача нужна, что ломается без неё.
3. **Что делать** — шаги, без воды.
4. **Критерии приёмки** — проверяемые пункты `- [ ]`; не «работает хорошо», а «на Android 14 запись не прерывается 2 часа, проверено логом».
5. **Связанные документы** — ссылки на `docs/`.
6. Если нужен ответ владельца — чек-лист вопроса и метка `needs-answer`.

## Правила работы с задачами

- **Одна задача = одна тема.** Всё «попутно» — новая задача.
- **Баг** описывается воспроизведением: шаги, ожидание, факт, лог/скриншот.
- Задача меняет статус через PR: `Closes #N` в описании коммита/PR закрывает её автоматически.
- Задача без критериев приёмки не берётся в работу: не о чем договариваться на приёмке.
- **Ответ владельца фиксируется в самой задаче** (комментарий), затем переносится в `docs/SPECS`,
  иначе следующий исполнитель не узнает, что решили.

## Как создать задачу

Быстро, через консоль (нужен токен в `secrets/.env` вне репозитория):

```bash
curl -s -X POST https://api.github.com/repos/dominumuniversi-cpu/v-voice/issues \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "Accept: application/vnd.github+json" \
  -d '{"title":"Короткий заголовок","body":"Проблема...\n\n## Критерии приёмки\n- [ ] ...","labels":["area/mobile","type/feature","phase/S1","p1"],"milestone":2}'
```
